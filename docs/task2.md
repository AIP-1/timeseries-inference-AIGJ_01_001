# 과제 2. 데이터 이해와 기준선

## 실행 (Jetson)

```bash
cd ~/jetson_AIGJ_01_001
docker compose --profile tools build lab
docker compose run --rm lab python -m analysis.export --days 400   # iot-bucket → data/history/*.parquet (처음엔 수 분)
docker compose run --rm lab python -m analysis.task2               # → data/reports/task2/report.md
```

`.env` 에 `INFLUX_ORG_ID`(강사 서버 org ID)가 있어야 한다. 토큰이 bucket 전용이라 org 이름은 조회되지 않는다.

## 설계 결정과 이유

| 결정 | 이유 |
|---|---|
| 데이터 원천은 강사 `iot-bucket` 실데이터 | 2025-09 이전부터 1년 넘게 쌓여 있어 합성 데이터가 필요 없다 |
| 범위 밖 값 버림 (co2 350~5000, 온도 0~45, 습도 1~99) | 0ppm·60℃ 는 측정이 아니라 고장. 보간하면 거짓 값을 학습한다 |
| 장비별 5분 평균 → 공간 평균 | 과제 3의 5분 간격 출력과 맞춘다. 공간 평균을 1분 단위로 먼저 내면 1·2·10분 주기 장비가 칸마다 들어왔다 빠지며 평균이 톱니처럼 흔들려(실습실 온도: 30분 예측 오차가 5분보다 작게 나옴) 장비별로 먼저 칸을 만든다 |
| 5분 칸 최소 개수는 장비 주기에 맞춤 (1분 장비 3개, 2·10분 장비 1개), 10분 장비는 다음 칸까지 값 유지 | 막 시작된 칸·끊김 직후 칸의 평균은 대표성이 없다. 고정 3개로 하면 10분 장비만 있는 회의실이 전부 비었다. 과제 8 서비스도 같은 규칙 |
| 5분 칸이 1% 미만으로 채워진 공간은 격자에서 뺌 | lab·강의실은 값이 2건뿐인 시험용 장비 |
| 15분 이하 결측만 보간 | 짧은 끊김은 CO₂ 가 크게 변하지 않는다. 긴 결측을 채우면 기준선·모델이 가짜 값을 맞히게 된다 |
| 시간순 분할, 마지막 28일 시험 · 그 앞 28일 검증 | 무작위로 섞으면 5분 이웃 값이 학습·시험에 나뉘어 들어가 성능이 부풀려진다 |
| 정규화 통계는 학습 기간만 | 시험 기간 분포가 새어 들어가는 누수 방지 |
| 기준선·모델은 `baselines.eval_points` 의 같은 시점에서만 평가 | 기준선마다 필요한 과거가 달라 평가 시점이 달라지면 비교가 공정하지 않다 |

`analysis/prep.py` 는 과제 8 상시 서비스도 그대로 import 한다. 학습과 서비스의 전처리가 다르면 같은 모델이 운영에서만 틀린다.

## 일정 자료

수업 시간표·예약이 아직 없어 "그날 새벽보다 CO₂ 가 100ppm 오른 첫 시각"을 사용 시작의 대리 지표로 쓴다(`onsets_<공간>.csv`). 시간표를 받으면 실제 일정과 이 시각의 차이(반응 지연)를 잰다.
