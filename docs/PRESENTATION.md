# 발표 원고 (5분) — 시계열 데이터 추론 실습, 강성찬 (AIGJ_01_001)

모든 수치는 실데이터(강사 InfluxDB `iot-bucket`, 2025-09-15 ~ 2026-10-20), 시험 기간 2026-09-22 ~ 10-20, 보드 MAXN_SUPER 기준. 자세한 표는 [REPORT.md](REPORT.md).

## 0. 한 줄 요약 (20초)

CO₂·온도·습도만 있는 교육장 4공간에서 60분 예측·이상 탐지·환기 경보를 Jetson 한 대로 매분 계산하는 서비스를 23시간 넘게 돌렸다. 과제 8개 중 1·2·4·6·7·8 통과, 3(CO₂)·5(F1)는 조금 미달이고 원인은 둘 다 같다: **재실 일정 자료가 없다.**

## 1. 무엇을 만들었나 (50초)

- 수집기: MQTT → 보드 로컬 InfluxDB. 24시간 커버율 99%(1분 센서), 97.9%(10분 센서). 재부팅 뒤 23초 만에 사람 손 없이 재개.
- 추론 서비스: 매분 공간마다 60분 예측·"몇 분 뒤 1,000ppm 초과"·이상 점수와 원인 센서·환기 선제 경보를 MQTT(retained)와 조회 API로 내보낸다. 1,386주기 실패 0, 주기당 1.4초.
- 수집기를 10분 껐을 때 모든 공간에 데이터 끊김 경보가 켜지고, 다시 켜자 1~7분 안에 꺼졌다.

## 2. 핵심 결과 세 가지 (1분 30초)

1. **예측(과제 3)**: GRU 가 60분 CO₂ 오차를 현재값 유지보다 22.9% 줄였다(목표 30%). 오차는 수업·회의 **시작 직전**에 몰린다. 과거 센서값에는 "곧 사람이 들어온다"는 신호가 없다.
2. **이상 탐지(과제 4)**: 오토인코더 + 규칙 결합으로 고장 67건 중 57건(85.1%) 탐지, 헛경보 하루 0.18회. 모델은 '값 고정'을 못 잡고(정상 범위에서 멈추면 조용한 정상과 같다), 규칙은 '냉방 정지'를 못 잡는다(서서히 오르는 온도). 둘이 서로의 빈 곳을 메운다.
3. **엣지 최적화(과제 7)**: TensorRT FP16 변환 뒤 CO₂ 예측 차이 최대 0.46ppm, 판정 뒤집힘 0%.

## 3. 가장 의외였던 발견 (1분 20초)

1. **GPU 가 CPU 보다 느렸다.** 이 크기 모델(GRU 수만 파라미터)은 ONNX Runtime CPU 0.21ms, TensorRT GPU 0.75ms. GPU 로 데이터를 보내고 받는 비용이 계산보다 크다. 그래도 PyTorch 를 버린 이유는 평균이 아니라 **느린 쪽 5%** 다: PyTorch 는 p95 가 평균의 4~7배로 흔들려 상시 서비스에서 다음 주기와 겹친다.
2. **쉬는 날에는 딥러닝이 '현재값 유지'보다 못했다.** 1차 실행에서 실습실 쉬는 날 오차가 GRU 11.6ppm vs 현재값 유지 4.9ppm. 모델이 "평일 아침이면 CO₂ 가 오른다"를 외웠기 때문이다. 공휴일 표시를 넣고, 검증 기간 성적으로 공간마다 GRU 와 현재값 유지를 섞어 해결했다.
   (여유가 있으면) 같은 실습실 센서 4대의 밤 기준선이 427~547ppm 으로 120ppm 차이 난다. 과제 4에서 '심은' 영점 틀어짐이 실데이터에 이미 있었고, 센서별로 세면 '기준 초과 비율'이 3.1%, 공간 평균으로 세면 1.2% 다.
3. **데이터 진단이 모델보다 먼저 성적을 바꿨다.** 회의실 센서가 10분 주기라 5분 칸이 전부 비어 있었고, 실습실은 2℃ 낮은 센서가 들락날락해 평균이 톱니였다. 이 둘을 고치자 기준선 오차부터 달라졌다(27.8 → 24.4ppm).

## 4. 미달 과제와 다음 행동 (40초)

- 과제 3 CO₂ 22.9%(목표 30%), 과제 5 macro-F1 0.608 vs 규칙 0.614. 하루·일주일 전 입력을 넣은 모델은 시험 기간에 0.637 로 규칙을 이겼지만, **검증 기간에서 졌기 때문에 채택하지 않았다.** 시험 성적을 보고 고르면 누수다.
- 두 과제의 공통 원인은 일정(수업 시간표·회의실 예약) 부재. 코드는 `--schedule` 로 받을 준비가 돼 있다.
- 운영 제안: 값 고정·튄 값·데이터 끊김은 설비 담당에게 즉시, 냉방 정지 의심은 냉난방 담당에게 하루 요약으로. 회의실 온도 센서는 분해능 문제로 점검 권고.

## 5. 마무리 (20초)

숫자보다 남는 것: 기준선을 먼저 재고, 검증 기간으로만 고르고, 모델이 못 하는 것을 규칙으로 메우고, 느린 쪽 5% 를 본다. 이 네 가지가 보드 한 대에서 23시간 돌아가는 서비스를 만들었다.
