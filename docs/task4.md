# 과제 4. 이상 탐지

실행 (보드, 과제 2 결과 필요): `docker compose run --rm lab python -m analysis.task4`
산출물 `data/reports/task4/`: report.md(성적표·임계값 표), summary.csv, event_results.csv, events.csv(주입 기록), alarms.csv, thresholds.csv, sweep.csv, ae.pt

## 설계 결정

| 항목 | 선택 | 이유 |
|---|---|---|
| 정답 | 시험 기간에 고장 5종을 직접 주입(공간 x 종류마다 4건, 시드 고정) | 실데이터에는 고장 기록이 없다. 주입 위치·크기는 events.csv 에 남겨 재현 가능 |
| 고장 모양 | 튄 값 1칸(CO₂ +300~800, 온도 ±3~8℃) / 값 고정 1~4시간(세 항목 함께) / 영점 3~6시간에 +200~400ppm 후 12시간 유지 / 냉방 정지: 사용 중 1~2시간에 +3~5℃ 후 2시간 유지 / 환기 정지: 사용 중 3시간 동안 새벽 대비 상승 폭 1.8배 | 과제 표의 설명을 그대로 수치로 옮김 |
| 모델 | 오토인코더(1시간 창 x CO₂·온도·습도 + 결측 표시 + 시각·쉬는 날 + 공간), 학습 기간으로만 학습 | 정상만 보고 배운다. 항목별 복원 오차가 원인 항목을 가리킨다 |
| 임계값 | 검증 기간(주입 없음)에서 헛경보가 하루 0.4회(전체 합) 이하가 되는 가장 낮은 값, 공간·항목마다 | 헛경보율을 직접 예산으로 둔다. 남은 0.6회는 규칙 몫 |
| 규칙 | 튄 값(앞뒤 칸과 크게 다름), 값 고정(CO₂ 30분, 온도+습도 1시간 같은 값), 새벽 기준선(영점 틀어짐 전용, B) | 모델이 약한 고장을 메운다 |
| 경보 합치기 | 같은 공간에서 1시간 안에 다시 울리면 한 건 | 운영자가 받는 알림 수 기준 |
| 탐지 판정 | 고장 시작~끝+30분 사이에 경보가 켜져 있으면 탐지, 지연 = 첫 경보 - 시작 | |
| 헛경보 | 어떤 고장의 시작 1시간 전 ~ 끝 2시간 후에도 걸리지 않는 알림 | 시험 기간의 진짜 이상도 헛경보로 세므로 보수적 |
